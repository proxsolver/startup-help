# 모두의 창업 정산 도우미 (비공식)

지원사업(모두의 창업) **참여자**가 사업비를 집행하고 지출증빙을 모아 정산·보고하도록 돕는
정적 안내 사이트 + 브라우저 전용 집행 정리 도구.

> 이 사이트는 중소벤처기업부·창업진흥원의 공식 안내가 아닙니다. 공식 안내는 [modoo.or.kr](https://modoo.or.kr) 입니다.

- 배포: GitHub Pages (정적 파일, 서버 없음)
- 사용자 데이터: `window.localStorage` 에만 저장. 어떤 입력도 네트워크로 전송하지 않음
- 콘텐츠 원칙: **제출 시점·한도·인정 범위 같은 수치는 1차 출처 검증 전에는 게시하지 않는다**

## 정리 도구가 갖는 항목 (스키마 v2)

한 건 = `{ 지출일, 거래처, 금액, 비목(예산과목), 결제경로, 집행기간, 증빙종류, 수취상태, 제출상태, 메모 }`

| 축 | 값 | 왜 따로 두나 |
| --- | --- | --- |
| 결제경로 | 전용(체크)카드 · 사업자·법인카드 · 개인카드 · 현금 · 계좌이체 · 간편결제 · 기타 · 확인 필요 | 어느 경로로 결제했는지가 받을 수 있는 서류를 정합니다 |
| 집행기간 | 기간 내 · 기간 외 · 확인 필요 | 기간 밖 지출이 정산에서 가장 많이 잘립니다 |
| 증빙종류 | 세금계산서 · 계산서 · 현금영수증 · 카드전표(매출전표) · 간이영수증 · 계약서·견적서만 · 없음 | 세무 일반 용어이며 정산 인정 여부와는 별개입니다 |
| 수취상태 | 원본 확보 · 사본·이미지만 · 미수취 · 재요청함 | 정산은 파일로 받습니다. 종류만 알고 파일이 없으면 미수취와 같습니다 |
| 제출상태 | 미제출 · 초안 포함 · 제출 완료 · 보완 요청 | 보완 요구를 목록으로 되돌려 받아야 합니다 |

비목은 협약서의 예산과목 이름을 그대로 쓰도록 **자유 입력(예시 목록 제공)** 으로 두었습니다.
집계 화면은 총 집행액 / 전용카드 비율 / 수취구멍 / 기간 리스크 / 제출 전 합계를 나오고,
CSV 는 12열 대조표(`execution_*.csv`, UTF-8 BOM + CRLF)로 나갑니다 — 승인번호가 `거래처` 다음 자체 열로 들어갑니다.
앞의 공백을 건너뛴 첫 글자가 `=`·`+`·`-`·`@` 인 값은 셀 앞에 작은따옴표를 붙여 **텍스트로 고정**합니다 — 인용 부호만 감싸면
엑셀·구글시트가 그 셀을 수식으로 계산해 버리기 때문입니다. 대조표를 정산 담당자에게 넘기는 사용법이 있으니
계산 시도가 자기 PC에서 끝나지 않습니다. 값은 지우지 않고 접두만 붙이고, 화면의 '자주 겪는 일' 에 그 이유를 적어 뒀습니다.
(CSV 를 되 읽어들이는 경로가 이 사이트에 없습니다 — 복원은 JSON 백업만 받습니다.)

**v1 데이터 호환**: 구버전 저장값(`category`, 결제수단 `카드`, `신용카드매출전표` 등)은
읽는 시점에 `sanitizeEntries → normalizeEntry` 에서 v2 로 승격됩니다. 판별은 v1 전용 필드
(`category` · `regularEvidence` · 결제수단 `카드`) 기준으로 하므로, v2 항목이 재승격으로 손상되지 않습니다.

**`schemaVersion` 은 한 번 오른 게 아니라 네 번 올라 지금 5 입니다**: `1 → 2`(항목 체계), `2 → 3`(삭제 기록 `removed`·복원 세대 `restoreAt` 도입), `3 → 4`(카드사 명세서 수입 설정 `cardSettings` 도입), `4 → 5`(승인번호 별도 칸 `approvalNo` · 보고서 머리 `reportMeta` 도입).
3으로 올린 이유는 강등 방지 때문입니다. 삭제 기록과 복원 세대를 모르는 예전 번들이 저장에 조용히 손을 대면
지운 행이 되살아나고 남의 복원을 덮어씁니다. 그래서 `isFutureSchema` 가 쓰기를 막습니다(읽기와 JSON 백업은 계속 가능합니다).
4번 `cardSettings` 는 지난 달에 정해 둔 **전용카드 끝번호 · 집행기간 · 가맹점→비목 규칙**을 다음 달 파일에 자동 적용하려면
지출 행과 함께 백업돼야 하므로 들어왔습니다. v3 저장본·백업에는 이 칸이 아예 없으니 `normalizeCardSettings` 가
**빈 설정으로 승격**합니다(추측 값으로 채우지 않음). `replaceEntries` 는 예외적으로 파일의 설정을 받아들인다가
파일에 규칙이 하나도 없으면 지금 값을 그대로 둡니다 — 오래된 백업이 규칙을 지워버리면 안 되니까요.

5번은 두 개를 한 번에 담습니다. ① **`approvalNo` 별도 칸** — 승인번호를 `메모` 텍스트에 섞어 두면 표·CSV·꾸러미에서
그 값이 열로 서지 않아 기관 대조 표에서 지워진 앞자리 0 과 함께 흩어집니다. 그래서 자체 필드로 옮기고, 지난 저장본에서는
`recoverApproval` 이 값을 되살립니다. 조건은 **두 개를 다** 봅니다: 행의 id 가 이 사이트 수입기가 만든 `sa-<숫자>` 이고,
그리고 **메모에 실제로 `승인 <그 숫자>` 조각이 들어 있을 때**만입니다. id 형식만 믿으면 안 되는 이유는 수입기 쪽에 있습니다 —
명세서에 승인번호가 없는 달에는 수입기가 조회번호·영수번호를 같은 id 자리에 넣기 때문에, 그 숫자만 보고 옮기면 승인번호가
아닌 값이 승인번호 열에 박히고 사용자가 빈칸으로 지운 승인번호가 다음 저장에서 되살아납니다(손으로 입력한 행 `r-…` 은
어느 쪽도 추측하지 않고 빈칸으로 남깁니다). 메모가 `승인 <번호>` 나 `승인 <번호> · …` 와 완전히 같은 모양일 때만 앞 조각을
지웁니다 — 같은 저장이 두 번 돌아가도 메모가 깎이지 않는다는 검사를 `tests/receipts.test.ts` 에 고정했습니다.
두 조건을 다 지킨 되찾기에도 남는 한계가 하나 있습니다: 예전 수입기는 열 이름이 `승인번호`든 `조회번호`든 `영수번호`든 같은
`approvalNo` 칸으로 읽어서 메모에 `승인 <그 값>` 으로 적었으므로, 오래된 저장본의 메모 조각 자체가 승인번호가 아닌
조회번호일 수 있습니다. 저장된 데이터만으로는 그 출처를 증명할 수 없고 사이트가 임의로 지우지도 않습니다 —
되찾은 값은 그대로 두고 화면에서 사용자가 확인·수정해야 합니다.
② **`reportMeta`** — 보고서에 들어갈
사업명·신청인·기관·정산 기간·연락처·특이사항을 지출 행과 같이 백업해야 다음 브라우저에서 다시 묻지 않으므로 들어왔습니다.
빈 설정으로 지금 값을 덮어쓰지 않도록 `hasReportMeta`(실제로 채워진 칸이 하나라도 있는지)로 판단합니다.

## 보고서 내보내기 (`src/lib/report.ts` · `src/lib/docx.ts`)

명세서를 넣고 화면이 물어본 것까지 채운 뒤의 마지막 걸음 — 화면의 표를 **문서**로 넘기는 자리입니다. `/tools/receipts/` 맨 위의
「내보내기」 카드에서 HTML · DOCX 두 파일을 받고(같은 카드의 「데이터 백업」이 CSV · 꾸러미 · JSON), PDF 는 HTML 을 열어 브라우저 인쇄 → PDF로 저장 으로 만듭니다.

- **모델 하나, renderer 둘**: `buildReport()` 가 만든 `Report`(머리·요약·표 3장)를 `reportToHtml()` 과
  `reportToDocxBody()` 가 나눠 씁니다. 숫자는 전부 화면과 같은 `computeTotals` · `evidenceGapList` 에서 나오므로
  파일과 화면이 서로 다른 값을 보여줄 수 없습니다(테스트로 고정).
- **모르는 것은 〔채우기〕**: 사업명·신청인·기관·기간처럼 사용자 입력이 없는 칸은 빈칸으로 두지 않고 자리표시자를 넣고,
  같은 목록(`REPORT_FIELDS`)이 화면의 「이것만 채워 주세요」 요청과 문서의 〔채우기〕 칸·주의색의 출처입니다.
  선택 칸은 요청 목록에 안 나오므로 문서에서도 `미기재` 로 나갑니다(빈칸과 채울 칸을 구분).
- **HTML 은 스크립트가 없습니다**: `<script>` 한 줄, 외부 자산 한 개 없이 `@page { size: A4; margin: 16mm; }` 만 담은
  단일 파일. 사용자 값은 `escapeHtml` 를 통과한 뒤에 들어가므로 붙여넣은 `<img onerror=…>` 은 글자로만 남습니다.
- **DOCX 는 zip 을 손으로 짜냅니다**: `[Content_Types].xml` · `_rels/.rels` · `word/document.xml` 세 조각,
  OPC 가 요구하는 deflate(`CompressionStream('deflate-raw')`) 로만 압축하고 CRC-32 를 직접 계산합니다
  (local·central 의 검사값·크기·시각이 반드시 같아야 하므로 압축 결과를 버퍼에 받은 뒤 헤더를 씁니다).
  한글은 Word 가 `eastAsia` 글꼴로 그리므로 모든 run 에 `w:rFonts w:eastAsia="맑은 고딕"` 를 실습니다 —
  지정이 없으면 판독기가 Times New Roman 같은 라틴 글꼴로 떨어져 깨져 보일 것으로 **예상**됩니다(Word 에서 비교해 본 검증은
  아닙니다). `styles.xml` 은 넣지 않고 크기·색을 run 마다 적되,
  **문단표시(`w:pPr/w:rPr`)의 글꼴·크기는 run 과 따로 실습니다**: Word 는 행 높이를 문단표시에서 계산해서, 빼면
  7.5pt 표 셀이 판독기 기본 크기까지 부풀고 표 사이 여백 문단까지 같이 늘어납니다(처음엔 파일 크기를 줄인다고 뺐다가 되돌렸습니다).
  복합글씨 지정(cs·bCs·szCs) 만 진짜로 빼고, 1,000 행 실측: `document.xml` 7.4MB → `.docx` **85KB**, 조립 84ms(Node v26 · vitest 안에서 측정).
  같은 조건의 사례를 `tests/docx.test.ts` 의 '1,000 행 보고서도 같은 zip 구조로 담기고…' 검사에 두었습니다 — 절대값은 기계에 따라
  달라지니 검사보는 관계(원문 1MB 이상 · 파일이 원문보다 작다)만 봅니다.
- **셀 값은 한 줄로 압니다**: 붙여넣기로 행 안에 개행·탭이 들어간 거래처명도 `w:t` 앞에 도달하기 전에 한 칸으로 줄입니다
  (`xml:space="preserve"` 는 그대로 두면 줄바꿈까지 보존합니다). 특이사항은 예외로 줄을 살려, HTML 은 `pre-wrap` 으로·
  DOCX 는 개행째 문단으로 나눕니다.
- **화면이 문서에 넘기는 것**: 「저장」을 누르지 않아도 아래 입력창의 지금 값이 보고서에 들어갑니다(`metaFromInputs()`).
  정산 기간은 **머리에 적어 둔 시작·종료 → 화면 필터 기간 → 행의 최소~최대 달** 순이고, 파일 이름은 문서에 적힌 기간을
  그대로 씁니다(머리와 이름이 다른 기간을 말하면 안 됩니다). 내보내기 고지의 〔채우기〕 개수도 화면이 따로 세지 않고
  방금 만든 문서의 칸을 셉니다(`reportBlankCount`) — 고지와 파일이 어긋날 수 없습니다.
- **검증 근거(2026-10-25, macOS)**: 조립한 파일을 `unzip -t`(Info-ZIP)로 무결점 확인, `xmllint --noout` 으로 XML 이 문법적으로
  서 있는지 확인, `textutil -convert txt` (Apple 의 DOCX 판독기)로 열어 본문·표·`01234567` 앞자리 0·`<검증용>` 이스케이프까지 그대로 나오는 것을 확인했습니다.
  브라우저(Chrome)에서 만든 파일도 그 안에서 zip 중앙 디렉터리를 다시 읽고 **local·central CRC·압축/원문 크기가 같고 deflate 를
  다시 풀어도 원문이 같은지**까지 확인했습니다.
  **Microsoft Word 에서 직접 열어 본 검증은 아직 없습니다** — 규격 최소 요건을 지켰고 세 개의 독립 판독기를 통과했지만,
  Word 의 수용성은 여기서 주장하지 않습니다.
- **PDF 를 직접 만들지 않는 이유**: 한글 글꼴을 파일에 심지 않고는 올바른 PDF 를 손으로 만들기 어렵습니다
  (Standard 14 서체에는 한글이 없고, 사전 정의 CMap 은 판독기에 이미 설치된 한글 글꼴 이름을 참조할 뿐이며, PDF/A 는 글꼴을
  심지 않은 파일을 허용하지 않습니다).
  그래서 인쇄 경로를 안내합니다 — 인쇄 대화창은 다운로드가 아니라 사용자 동작입니다.
- **문서에 들어가는 것과 들어가지 않는 것**: 특이사항(`reportMeta.note`)은 「특이사항」 절로 **들어갑니다** — 기관에 미리 알릴
  내용을 사용자가 직접 적은 것이기 때문입니다. 들어가지 않는 것은 행의 `메모` 입니다(테스트로 고정). 메모는 수입기가 남긴
  카드사 원문 조각(`일시불 · …`)까지 섞여 있어, 그대로 문서에 흐르면 정산 자료와 명세서 사본이 구분되지 않습니다.
  집행 목록 표에 나는 열은 아홉 개(지출일·거래처·승인번호·금액·비목·결제경로·증빙 종류·수취·제출)로, 화면 표의 데이터 열에서
  **`집행 기간`과 `메모`를 뺀** 값입니다(화면의 `지우기` 열은 버튼이라 애초에 문서에 대응하는 값이 없습니다).
  집행 기간은 행별로 다시 적지 않고 요약 행 `기간 확인 필요·기간 외`(건수·금액)으로 묶어 말하며, 문서 머리의 정산 기간은
  사용자가 적거나 화면·데이터에서 골라 쓴 기간 문자열입니다 — 행의 `periodState` 를 대신 검증하지는 않습니다.
  메모는 위와 같은 이유로 들어가지 않습니다.
- **화면 실측(2026-10-25, Chrome · `astro preview` · 지어낸 3행 저장본)**: 「저장」을 누르지 않고 입력창만 고쳐도 보고서가 그 값을
  담고, 필수 두 칸(사업명·주관 기관)을 지우면 ① 「이것만 채워 주세요」 목록이 그 자리에서 정확히 그 두 항목으로 줄고
  ② 내보내기 고지의 개수(`… · 입력창에 값이 없는 2칸은 문서에 〔채우기〕로 남았습니다`)가 ③ 파일 안 자리표시자 개수(2)와
  일치했습니다. 파일 이름은 문서에 적힌 기간을 따라 `report_2026-08-01-2026-10-31_20261025.html`·`.docx` 로 나옵니다.
  내려받은 DOCX(3,997바이트) 는 페이지 안에서 zip 중앙 디렉터리를 다시 걸어 세 항목 모두 local·central CRC·압축/원문 크기가
  같고 deflate 를 다시 풀면 원문이 같음을 확인했습니다. 본문 `document.xml` 의 `w:pPr` 110개에 문단표시 `rPr` 이 110개(행 높이
  계산용 글꼴·크기가 빠진 문단 없음), 승인번호 `01234567` 은 앞자리 0 을 글자로 유지, `<script>` 0건, 콘솔 오류·경고 0건.
- **검사 시간대와 무관하게**: 작성 각인과 파일 이름은 로컬 달력을 읽습니다. 같은 검사를 `TZ=Pacific/Niue`(UTC-11) 와
  `TZ=Pacific/Kiritimati`(UTC+14) 에서 돌려 259건 모두 통과합니다 — ISO 문자열로 고정한 예전 방식은 UTC-11 에서 하루가 밀렸습니다.
- **네 산출물의 파일 이름 날짜는 한 곳에서 납니다.** `src/lib/receipts.ts` 의 `dayStamp()` 만 쓰고, CSV·정산 꾸러미·보고서(HTML·DOCX)·
  JSON 백업이 모두 그것을 읽습니다. 고치기 전에는 CSV(`receipts.csvFileName`)와 JSON 백업(`storage.backupFileName`)이
  `toISOString()` 을 잡아 UTC 날짜를 붙였고, 꾸러미·보고서는 로컬 날짜를 붙였습니다 — 한국에서 0 시~9 시 사이에 내려받으면
  같은 화면에서 받은 네 파일 중 둘은 어제, 둘은 오늘 날짜가 붙었습니다(2026-10-27 01:35 실측: `execution_..._20261026.csv`·
  `startup-help-backup_20261026.json` vs `kkureomi_..._20261027.txt`·`report_..._20261027.html`). 위 134행의 "파일 이름은 로컬 달력을
  읽습니다" 가 사실이 아니었던 셈이라, 이제 문서와 코드가 맞습니다.

## 카드사 명세서 파일 수입 (`src/lib/cardimport.ts`)

`/tools/receipts/` 화면에서 `.xlsx`·`.csv`·`.tsv` 파일을 고르거나 끌어다 놓으면 집행 행으로 바꿉니다. **추가 단추를 누르기 전까지는 저장되지 않습니다.**

- **패키지 없음**: `.xlsx` 는 zip 이므로 직접 풉니다 — 중앙 디렉토리를 읽고, 항목은 브라우저가 이미 가진
  `DecompressionStream('deflate-raw')` 로 펼칩니다(Chrome 103 · Safari 16.4 · Firefox 113 이후, node 18+ 도).
  XML 은 관용 문자열 스캐너(`chunks`)로 훑습니다 — node 에는 `DOMParser` 가 없어서 양쪽에서 동작하는 해석기가 필요합니다.
  압축 풀 기능이 없는 오래된 브라우저에서는 `.xlsx` 가 실패하고 안내가 나옵니다. **CSV·TSV 는 압축 없이 읽히므로 폴백**입니다.
- **값이 아니라 내용으로 종목 판정**: 앞 2바이트가 `PK` 면 xlsx, 아니면 텍스트. 확장자가 거짓말을 해도 됩니다.
  텍스트는 UTF-8(`fatal: true`) 실패 시 EUC-KR 로 재시도 — 엑셀 'CSV로 저장' 기본값이 EUC-KR 입니다.
- **양식이 알려 주지 않은 것은 비워 둡니다**: 결제경로는 사용자가 알려 준 카드 끝번호가 이용카드 문자열에
  포함될 때만 `전용(체크)카드`, 아니면 `확인 필요`(선불·후불 표기로 개인카드인지 추측하지 않음).
  집행기간도 기간 미지정 시 `확인 필요`. 수취상태는 **모두 미수취** — 명세서는 전표 원본이 아니라서
  자동 '원본 확보' 로 우기면 이 사이트가 정산 구멍을 덮어주는 셈이 됩니다.
- **남은 질문만 보여 줍니다**(`gaps`): 카드 미지정 · 비목 미지정 · 기간 미지정 · 건너뛴 행 · 인식 못 한 열 · 증빙 미수취.
  설정을 다 채우면 남는 것은 증빙 확보 한 개뿐입니다(테스트로 고정).
- **합계 행 방어**: `총 1건`·`합계`·날짜/금액 없는 행은 집행 행으로 세지 않습니다. 안 그러면 금액이 두 배로 부풀어 오릅니다.
- **id 는 승인번호 우선**(`sa-01234567`, 앞자리 0 보존) → 같은 파일을 두 번 넣으면 화면이 '이미 있던 N건 건너뜀' 으로
  처리하고, 지난번에 **지운 행은 되살리지 않습니다**(삭제 기록이 그 id 를 기억).
- **상한**: 파일 `MAX_IMPORT_BYTES` 8MB(넘으면 읽지 않고 사유), 끝번호 20개·조각 12자, 규칙 300개·조각 60자/비목 60자.
  백업 파일 하나로 화면을 늘어지게 못 가게 하는 방어입니다(저장소 상한과 같은 이유).
- **실측 검증(2026-10-25)**: 실제 신한카드 내역 파일을 브라우저(`astro preview`)에 올려 열 열세 개가 전부 매핑되고
  인식 못 한 열이 없는 것(`unknown: []`, `missing: []`)까지 확인했습니다. 확인한 것은 **값이 아니라 값의 형태**입니다 —
  점 구두점 거래일에 시각이 붙어 있고, 승인번호에 앞자리 0 이 남고, 금액에 소수점이 붙고, `총 1건` 합계 행이 집행 행으로
  세지지 않고, 한 번 채운 설정으로 질문이 네 개에서 한 개로 줄고, 정산 꾸러미에 그 행이 들어가는 것까지 봤습니다.
  **거래일·가맹점명·승인번호·금액의 실제 값은 이 리포에 넣지 않았습니다**(사용자 명세서 데이터입니다). 검사 픽스처는
  검사 중에 zip 을 조립해 만들고 거래처명·승인번호·금액은 지어낸 값입니다(`tests/cardimport.test.ts`).
- **서버로 보내지 않는다는 말의 근거**: 같은 세션의 네트워크 기록에 이 사이트에서 나가는 정적 `GET` 요청만 남고
  `POST`·외부 도메인 요청은 없었습니다. 코드에 `fetch`·`XMLHttpRequest`·`sendBeacon` 이 0건이라는 위 '보안 관점' 사실과도 맞습니다.
- **아직 모르는 한계**: 끌어다 놓기 경로는 브라우저에서 합성 `DragEvent` 로만 확인했습니다 — 실제 OS 드래그로 놓아 보는 검증은 못 했습니다.
  (예전에 한계로 적어 둔 「승인번호가 메모에만 있다」 는 `schemaVersion` 5 로 해제되었습니다 — 이제 표·CSV·꾸러미·보고서(HTML·DOCX) 모두에 승인번호 열이 있습니다.)

## 저장 규칙 (브라우저 전용, 그래서 더 엄격하게 지킨 것들)

`window.localStorage` 의 `startup-help/state/v1` 한 개 키에 담습니다. 서버는 없습니다.

| 상황 | 동작 |
| --- | --- |
| 두 탭이 열려 있을 때 | 쓰기 직전 저장된 값을 다시 읽어 **항목 단위로 합칩니다** (`mergeEntries`). 한 탭의 입력이 다른 탭 저장에 사라지지 않고, 다른 탭이 저장하면 `storage` 이벤트로 화면에 반영됩니다 |
| 삭제한 항목 | 지운 id 를 저장소의 `removed` 에 남깁니다. 오래 열어 둔 다른 탭이 같은 id 를 다시 보내도 되살아나지 않습니다. 화면·저장소·백업이 **같은 목록 하나**를 씁니다(`state.removed` 단일 출처). 최근 2,000개까지만 기억하고, 밀려나면 몇 건을 잊었는지 화면에 띄웁니다 |
| 백업 복원 | 목록은 **대체**, 체크리스트는 보존, 삭제 기록은 비웁니다. 대체 시각 `restoreAt` 을 찍어 세대 표식으로 씁니다 |
| 복원과 오래된 탭 | `restoreAt` 이 자기 것보다 새로우면 그 탭은 저장을 포기하고 복원 결과를 받아들입니다(`superseded`). 복원 전에 열린 탭의 삭제 기록이 방금 복원된 행을 지우는 일을 막습니다 |
| 같은 항목을 두 탭에서 고칠 때 | 마지막 저장이 승리합니다(항목 단위의 `updatedAt`·리비전은 없습니다). 같은 행을 두 탭에서 동시에 편집하는 경우만 주의하세요 |
| 지출 저장 vs 체크리스트 저장 | 각각 자기 영역만 씁니다 (`saveEntries` / `saveChecklist`). 한 화면의 저장이 다른 화면의 데이터를 덮어쓰지 않습니다 |
| 저장된 데이터가 이 코드보다 새로운 스키마 | **쓰기를 거부**하고 읽기만 합니다. 형식 강등은 되돌릴 수 없어서입니다 |
| 읽지 못한 행 | 개수를 화면에 표시합니다(조용히 버리지 않음) |
| 더 새로운 형식의 백업 파일 | 복원하지 않음(형식 강등을 막습니다) |
| 복원 파일이 너무 클 때 | **아예 읽지 않습니다.** 세 개의 상한을 순서대로 통과해야 복원이 진행됩니다 — ① 파일 크기 20MB(`isBackupFileTooLarge`, 파일을 열기 전) ② 지출 행 5,000건 ③ 삭제 기록 id + 체크리스트 키 100,000개(②③은 `parseBackup` 이 렌더링 전에 판단). 서버가 없어 복원 전 과정이 이 탭 안에서 일어나므로 '저장소에 안 들어간다' 는 방어가 아니고, 50,000건은 저장 키 13~19MB(같은 코드로 재본 값: 행 하나당 저장 키 275~384 B, 백업 파일은 줄바꿈·들이쓰기 때문에 약 35% 더 큼) 로 용량 초과 실패 경로에 들어가기 *전에* 표 렌더링부터 멈춥니다. 거부된 시도는 저장소를 건드리지 않고, 거부 결과에는 `state` 가 아예 들어 있지 않아 호출이 `rejected` 를 잊어도 목록을 바꿀 수 없습니다(판별 연합) |
| 지출 목록 비우기 | 지출만 삭제. 체크리스트는 그대로 |
| 시크릿 창·용량 초과 | 저장이 실패함을 배너로 보여줍니다 |

## 보안 관점 (2026-10-25 수동 감사)

전용 스캐너 없이 저장소 도구(코드 전체 그리프, `npm audit`, `gh api`, 빌드 후 `dist` 확인)로 감사했습니다.

**이 사이트의 공격면은 구조로 먼저 줄어 있습니다.** 서버·API 키·로그인이 없고, 클라이언트 코드에
`fetch`·`XMLHttpRequest`·`WebSocket`·`sendBeacon`·`EventSource`·serviceWorker 가 **0건**입니다
(→ "서버로 데이터를 보내지 않는다" 는 개인정보 문구가 코드 사실과 일치). 렌더링은 전부 `textContent` 라
`innerHTML`·`outerHTML`·`eval`·`new Function`·`document.write` 도 **0건** — 복원한 파일에 스크립트가 섞여 있어도 화면에는 텍스트로만 나옵니다.
레이아웃에 서드파티 `<script>`·웹폰트가 없고, `target="_blank"` 6개는 전부 `rel="noopener noreferrer external"` 을 가집니다.
저장은 `localStorage` 키 하나, `dist` 에 sourcemap 없음, 트리에 시크릿 없음.

**이번에 막은 것**
- CSV 수식 주입 (공백 뒤 숨은 `= + - @` 시작 셀 포함) → 앞의 '정리 도구' 단락 참조. `tests/receipts.test.ts` 가 접두까지 정확히 검증합니다.
- 백업 복원 상한 (파일 20MB·행 5,000건·기록 100,000개) → 앞의 '저장 규칙' 표 참조. 세 상한 모두 `tests/storage.test.ts` 에 경계값(상한과 같은 값은 통과, +1 은 거부)으로 두고, 실제 브라우저(로컬 프리뷰)에서 5,001건·21MB 파일이 거부되고 3건은 복원되는 것과, 거부 시 저장소가 그대로인 것을 확인했습니다.

**알고도 남기는 것**
- `npm audit` 의 프로덕션 경고 5건(astro critical·sharp/zod-to-ts high·esbuild low). 진입점을 확인했더니 `define:vars` 0건, `set:html`·`is:raw` 0건,
  `astro:assets`·원격 이미지 0건, `src` 의 `zod` 직접 import 0건 — **이 사이트 빌드에서 그 코드가 실행되지 않습니다.**
  해소는 `astro@7` breaking 업그레이드라 별도 작업으로 미룹니다(올리면 콘텐츠 게이트·링크 검사가 같이 붙어야 합니다).
- GitHub Pages 는 응답 헤더를 설정할 수 없어 CSP·`X-Content-Type-Options` 을 걸 수 없습니다. 서드파티 스크립트가 0건이라 실질 이득은 작고,
  대신 `<meta>` 로 넣을 수 있는 것만 넣는 판단을 합니다.
- 콘텐츠 게이트는 **출처 주소의 형식**만 봅니다. 카드사 페이지에 적힌 번호·경로의 진실성은 CI 가 검증하지 못하므로
  사람이 원문을 열어 확인한 시점을 문서에 적어 둡니다.

## 화면·메뉴 규칙 (문서를 한 장 추가할 때)

- **분류가 곧 메뉴입니다.** `src/data/categories.ts` 의 4개 분류가 헤더 메뉴·`/guide/` 목록·분류 페이지·홈의 '문서로 찾기' 카드를 모두 구성합니다. 새 문서는 `category` 와 `order` 로 제자리를 찾고, 홈의 '자주 찾는 순서대로' 는 `order <= 2` 만 올라갑니다.
- **문서 한 장의 모양은 고정**입니다. frontmatter 는 `title`·`summary`(한두 호흡)·`tags` 5개 이하·`order`, 본문은 바로 `##` 소제목으로 시작하고 `## 관련` 으로 끝납니다. 출처 목록("확인할 곳")·"같은 분류의 다른 안내"·면책 고지는 `[slug].astro` 가 자동 첨부하니 **본문에서 같은 면책을 다시 쓰지 않습니다**.
- 제목은 **할 일 기준**으로 적습니다(예: `카드사에서 서류 받아오기`). 특정 회사·기관 이름은 제목보다 `tags` 와 소제목(`## 신한카드에서 확인한 창구`)에 두면, 다른 카드사 문서를 같은 칸에 이어 붙일 수 있고 목록에서 한 장만 동떨어져 보이지 않습니다.
- 문서 이름·주소를 바꿀 때는 옛 주소를 `src/pages/guide/<분류>/<옛 slug>.astro` 리다이렉트 한 장으로 받습니다. GitHub Pages 는 서버 리다이렉트가 없고, 이미 열어 본 주소가 404 로 남으면 당황스럽습니다. 이 화면은 `noindex` + canonical 을 새 주소에 걸어 중복 문서로 번지지 않게 합니다(`check:dist` 의 canonical·(비공식) 규칙 통과).

- **표 전체의 최소 너비만 풀고 페이지 폭에 맞춥니다.** 화면용 하한은 `min-width: 0` + 래퍼 `overflow: visible` 로 내리지만, 첫 열 하한 6rem 은 인쇄에서도 남깁니다.

- **알약 표시(`.badge`) 도 인쇄에서는 감쌉니다.** 화면처럼 한 줄로 묶으면 그 단어 길이가 열의 최소 폭을 결정해 시점 열이 103px 를 차지하고 옆 열이 25px 까지 눌렸습니다(360px 인쇄 실측).
  인쇄에서 감기게 두니 표가 페이지 안에 다시 들어옵니다.
- **칸 안의 긴 단위(주소·영문 단어) 는 종이라 잘라 먹습니다.** `overflow-wrap: anywhere` 는 최소 폭 계산에도 반영돼, 본문 칸이 좁은 종이에서도 표가 페이지를 넘지 않게 막습니다.
- 816px 인쇄 매체 실측: 12열 지출 목록 928px → 724px · 6열 캘린더 704px → 752px · 4열 문서 지도 448px → 594px · 3열 안내 표 → 594px · 3열 요약 표 → 724px.
  페이지 너비 넘침 없음(body 816px), 잘린 요소 없음, 표 안 글자도 줄입니다(9pt). 색을 직접 적는 유일한 자리가 인쇄 규칙입니다(`body` 의 `#fff`·`#000` 와 링크 주소의 `#444`) — 종이는 테마를 타지 않기 때문입니다.

- **다크 화면을 인쇄하면 2층을 라이트 정의와 같은 값으로 되돌립니다.** 기존 인쇄 규칙은 `body` 만 흰 바탕/검은 글자로 바꿔 두어, 면·글자를 스스로 입히는 요소는 짙은 배경에 검은 글자로 남았습니다(고치기 전 816px 다크 인쇄 실측: 카드 `#1b1f27` 위 `rgb(0, 0, 0)` 1.27:1 · 안쪽 면 `#222731` 위 1.4:1 · 경고 안내 `#2a2314` 위 1.35:1 · 링크 `#7ab0ff` 는 흰 종이에서 2.21:1).

### 시각 개편 (2026-10-27) — 레이아웃·톤만 고친 것

기능·데이터 로직(`src/lib/*`) 과 검증 게이트 다섯 개는 그대로 두고, `src/styles/global.css`·레이아웃·컴포넌트 마크업·`src/plugins/tableScroll.js` 만 고쳤습니다.
게이트는 개편 후에도 모두 초록입니다(콘텐츠 10건 · `astro check` 오류 0 · 테스트 259건 · 빌드 27페이지 · dist 내부 링크 612건).

- **`global.css` 의 `:root` 를 세 층으로 나눴습니다.** 1층 원시값(`--p-*` — 라이트·다크 색과 그림자 농도) → 2층 의미(면 `--page`·`--card`·`--inset`·`--chip` / 글자 `--ink-1`~`--ink-3` / 선 `--line`·`--line-strong` / 강조·상태 `--accent`·`--ok`·`--warn`·`--danger` + 각각의 wash / 그림자 `--shadow-near`·`--shadow-far`) → 3층 부품(`--t-*` 타입·`--g-*` 여백·`--r-*` 모서리·`--sh-*` 그림자·`--tw-*` 표 폭·`--num` 숫자).
  화면 규칙은 3층까지만 읽고, 색 리터럴은 1층에만 있습니다 — 다크 화면과 다크 인쇄는 2층 이름을 1층 값으로 다시 매핑하기만 하는 교체 블록(`--p-dark-*` · 인쇄용 라이트 매핑) 두 개입니다. 남은 예외는 테마를 타지 않는 인쇄의 종이 색(`#fff`·`#000`·`#444`) 한 자리이고, 파일 맨 위 주석에 이 규칙을 적어 두었습니다.
  내려받는 보고서 HTML(`src/lib/report.ts`) 은 사이트 시트지를 공유하지 않는 별도 문서라 자체 색을 그대로 가집니다.
- **레이아웃 토큰을 새로 만들었습니다** — `--shell: 1080px`·`--gutter: clamp(1rem, 4vw, 2rem)`·`--header-min: 58px`. 거터는 화면 800px 이상에서 32px 로 고정됩니다.
- **본문 위 여백이 0 → 20px 가 되었습니다.** 개편 전에는 첫 제목이 헤더의 1px 테두리에 곧바로 닿았습니다(실측 간격 0). 이제 헤더와 첫 요소 사이는 모든 폭에서 20px 입니다(360·390·780·800·1440 실측).
- **붙박이 헤더를 실측으로 정리했습니다.** 한 줄일 때 59px(1440px) · 800px 에서 82px · 두 줄로 접히면 107px(360·780px). 브랜드 이름에 걸었던 자간 `-0.02em` 은 한글에서 받침과 다음 글자의 초성을 서로 먹히게 해서 풀었습니다(`normal` · 브랜드 폭 245×28px 실측).
- **화면 안의 인라인 `style` 을 전부 클래스·커스텀 프로퍼티로 흡수했습니다.** `src/components`·`src/pages`·`src/layouts` 의 `style="…"` 이 77개 → 0개가 되었고, 집행 정리 도구의 DOM 안 인라인 스타일 노드도 0개(1440px 실측) 입니다.
- **글자·대비·숫자를 확인했습니다.** 본문 17px·줄높이 29.24px(1.72) · h1 36px(1440px)/25.6px(360px). 텍스트 대비는 8화면 × 라이트/다크 실측 최저 5.16:1 · 5.74:1 로 4.5:1 미만 0건입니다(가장 옅한 자리는 집행 요약의 12px 항목 이름).
- **숫자가 들어가는 칸은 자릿수를 세로로 맞춥니다.** `font-variant-numeric: var(--num)`(= `tabular-nums`) 을 금액·건수 열(`.num`), 지출일·승인번호처럼 잘리면 의미가 깨지는 열(`.keep`), 집행 현황의 값(`.stats dd`), 날짜·숫자 입력에 걸었습니다. 본문 마크다운 표에는 금액·숫자 열이 없어서(전 문서 조사) 추가 규칙을 두지 않았습니다.
- **키보드 포커스가 그리는 자리에 남습니다.** `:focus-visible` 은 3px 실선 + 2px 띄움(라이트 `#1f56c9` · 다크 `#7ab0ff`)이고, 파일을 통틀어 `outline` 을 지우는 규칙은 없습니다. 6화면 × 라이트/다크 × 탭 14회 = 168회 정지 실측에서 본문 요소는 모두 테두리가 그려졌습니다. 날짜 입력의 네 번째 정지만 초점이 안쪽 「달력 열기」 단추로 넘어가 브라우저가 자기 테두리를 그립니다(캡처 확인).
- **필요한 정보는 마우스를 얹어야만 드러나지 않습니다.** `:hover` 규칙은 링크·헤더 메뉴·카드·표 행·버튼 등 7곳뿐이고 모두 색만 바꿉니다 — `display`·`visibility`·`opacity` 로 내용을 여닫는 규칙은 없습니다.
- **창 색(`theme-color`) 을 붙박이 헤더 면에 맞췄습니다**(`#f5f6f8` · 다크 `#14171c`). 브랜드 파랑으로 칠했을 때는 헤더는 옅은 회색인데 창 맨 위만 짙은 파랑으로 떴었습니다. 값은 1층 원시값의 사본이라 `Base.astro` 주석에 함께 고치라고 적어 두었습니다.
- **다크 모드·`prefers-reduced-motion` 은 지우지 않고 새 토큰으로 옮겼습니다.** 화면용 다크 블록이 2층을 1층 `--p-dark-*` 값으로 바꿔 끼우고, 인쇄에서는 위 인쇄 섹션의 매핑이 2층을 라이트 정의값으로 되돌려 종이 색이 됩니다.

### 오퍼는 한 파일, 상태는 두 개

`src/data/offer.ts` 가 유료 문장의 유일한 출처입니다(`status` · `who`/`whoBasis` · `scope` · `services[]` · `contact` · `privacy`).
`src/lib/offer.ts` 는 그 값만으로 판정하는 순수 함수들(`offerLive` · `publishableServices` · `contactHref` · `offerProblems` …)이고, 화면은 두 파일만 봅니다.

- `status: 'preparing'` (기본값) → `offerLive()` 가 false, `Offer.astro` 는 아무것도 그리지 않습니다. 지금 배포물에는 상업 마크업이 0개입니다(`grep -r "offer-" dist` → 0건).
  좁혀서 말하면: **CTA·항목 카드·문의 창구·개인정보 고지**가 0건이라는 뜻이고, 내비의 「도움 요청」 과 `/consult/` 페이지 자체는 남아 있습니다. 닫힌 상태의 `/consult/` 은 「지금은 꺼 놓았습니다」 + 셀프 진행 경로만 보여 줍니다 — 받을 곳이 없는 광고 문장을 만들지 않는 선이지, 페이지를 숨기는 선은 아닙니다.
- `status: 'open'` → 연락처가 유효하고 게시 조건(제목·설명·범위 경계·게시 근거)을 통과한 항목이 1개 이상일 때만 화면에 나옵니다.

### 게이트: 창구를 여는 순간 필수 칸

같은 규칙을 두 곳에서 봅니다.

1. `scripts/check-content.mjs` 규칙 9 — `open` 에서 `who`·`whoBasis`·`scope`·`contact.value`(형식 포함)·항목별 `title/desc/notFor/basis`·`privacy.collects/purpose/retention/refusal` 을 요구합니다. 빈 칸이 있으면 빌드가 멈춥니다. `preparing` 은 필드가 비어도 통과합니다(화면에 안 나오니 진술도 없음). 다만 `contact.value` 형식은 준비 중에도 봅니다.
2. `tests/offer.test.ts` — 판정 함수 `offerProblems` 에게 같은 실제 데이터를 돌려 앞으로의 변경을 지킵니다. `status` 를 open 으로 커밋하는 순간 필수 칸이 채워져 있어야 통과합니다.

두 판정 로직이 완전히 같지는 않습니다: 스크립트는 open 이면 `privacy` 를 무조건 요구하지만, lib 는 창구 값이 있을 때만 요구합니다.
연락처 없는 open 은 어느 쪽에서든 이미 실패하므로 '스크립트가 덜 막는' 방향의 어긋남은 없고, 엄격함은 스크립트 쪽으로만 치우쳐 있습니다.
`privacy.collects` 는 이제 양쪽 모두 빈 배열을 막습니다(lib 는 `filter(filled).length === 0` 로 판정 — `'  '` 만 늘어 놓으면 화면에는 항목이 없는 것처럼 보이지만 고지는 성립하지 않습니다).

3. `tests/offer.test.ts` 의 '게이트 규칙 9 ↔ offerProblems 일치' — 위 1·2 가 서로 다른 칸을 보지 않는지 **스크립트 원문을 대조**해 확인합니다. lib 가 `open` 에서 요구하는 칸이 규칙 9 에도 적혀 있어야 통과하는 방향(약한 쪽이 먼저 통과해 게시되는 사고 방지). 독립 검토가 딱 이 어긋남을 하나 찾아냈습니다: 규칙 9 는 `collects: []` 문자열만 보고 `['']`·`['  ',' ']`·줄 삭제를 통과시켰는데, lib 는 막았습니다 → 규칙 9 를 내용 판정으로 고치고 이 테스트로 못박았습니다.

같은 검토에서 나온 두 가지도 함께 고쳤습니다.
- **규칙 6 의 접두 목록을 라우트에서 파생**: 문서 본문 검사는 `/privacy/`·`/terms/`·`/disclaimer/` 접두가 목록에 없어 오타 링크가 본문 검사를 지나 빌드 검사에서만 잡혔습니다. 이제 본문 검사(`isInternalLink`) 와 코드 검사(`CODE_LINK`) 모두 `src/pages` 에서 만든 `LINK_ROOTS` 를 공유합니다.
- **canonical 의 base 이중 부착**: `/start/`·`/consult/` 가 `path={p('/start/')}` 로 이미 감싼 값을 레이아웃에 넘겼고, 레이아웃의 `absoluteUrl` 이 한 번 더 감싸 `…/startup-help/startup-help/start/` 가 나갔습니다(dist 실측). 두 페이지에서 `p()` 를 빼고, `p()` 자체도 base 가 붙은 입력은 그대로 두도록 만들고, `check:dist` 가 "canonical 에 base 가 2번 이상 붙으면 실패"로 회귀를 막습니다.

**알려진 한계 (방향은 안전측)**: 규칙 9 는 `offer.ts` 를 import 하지 못하고 정규식으로 읽습니다. 그래서 큰따옴표·백틱·상수 참조로 적힌 값은 빈 문자열로 보여 '빈 칸' 오진을 낼 수 있고, 값 안에 `'` 가 있으면 캡처가 중간에 잘립니다(예: `'don't'` → `'don`). 둘 다 "필요 이상으로 막는" 방향이라 게시 사고로 이어지진 않지만, 값이 이상하게 읽힌다고 나오면 `npm test` 의 `offerProblems(OFFER)` 결과를 기준으로 판단하세요.

### 운영자가 채우는 순서

`src/data/offer.ts` 비어 있는 필드를 1) contact → 2) privacy → 3) who/whoBasis/scope → 4) services → 5) `status: 'open'` 순서로 채운 뒤 `npm run check:content` 를 돌리면 남는 칸이 나옵니다.

값을 제가 채우지 않은 이유와 경계:
- **가격·회신 시간·실적·자격** 은 운영자만 아는 사실입니다. `price` 가 비면 "미정" 이나 "상담에서 안내" 같은 대체 문구도 만들지 않습니다.

- **`basis`**(`whoBasis`·`contact.basis`·`services[].basis`) 는 그 문장을 게시할 근거입니다. 비면 그 항목은 화면에서 사라집니다.

## 검증 상태 모델 (핵심 설계)

문서·정산 항목마다 `verification: 'verified' | 'pending'` 을 가집니다.

| 상태 | 화면 동작 |
| --- | --- |
| `pending` | 문서 상단에 "출처 검증 대기" 배너. 시점·금액은 **빈칸** + 공식 창구 링크. 푸터에 대기 건수 표시 |
| `verified` | 배너 없음. 검증된 값과 출처가 본문·`sources` 에 존재 |

`pending` 문서가 `만원`/`억원`/`가산세`/`제N조`/보존기간·기한 수치를 쓰면 `npm run check:content` 가 빌드를 실패시킵니다.
같은 게이트가 한자·가나 섞임 문자도 전체 소스에서 잡아냅니다.
즉 "임의 수치를 올리지 않는다" 가 사람의 주의가 아니라 CI 규칙으로 강제됩니다.

출처 도메인의 기본 허용 범위는 공공 기관 영역(`go.kr`·`or.kr`·`gov.kr`)입니다. 다만 **카드 발급 창구·ARS 버튼 경로·발급 권한**처럼
기관 사이트에 애초에 없는 정보는 그 회사 안내 페이지가 1차 출처라서, 사람이 원문을 직접 열어 확인한 회사 도메인만을
`scripts/check-content.mjs` 의 `ISSUER_SOURCES` 에 낱개로 등록해 예외로 둡니다(현재 신한카드 한 곳). 예외 도메인은
frontmatter 의 `label` 에 회사 이름이 들어 있어야 통과합니다. 같은 도메인 제한은 **본문에 걸은 외부 링크**에도 적용됩니다 —
frontmatter 만 보면 글 속의 블로그·기사 링크가 무방비로 통과해서, 사도메인 차단이 껍데기만 남기 때문입니다.
`evil-shinhancard.com`·`shinhancard.com.attacker.tld` 처럼 허용 도메인을 부분 문자열이나 접미사로 흉내낸 host 는
`new URL().hostname` 의 정확 일치·점 접미사 판정에서 걸립니다(시험 확인).

이 예외가 덮지 못하는 한계도 적어 둡니다 — 게이트는 출처 **주소**만 봅니다. 카드사 창구 값(ARS 버튼 순서·조회 가능 기간·
전화번호)이 실제 페이지에 적혀 있는지는 CI가 확인하지 못하므로, 사람이 원문을 열어 확인한 날짜를 문서 본문에 남기고
확인하지 못한 값(수수료·처리 소요·오래된 내역 조회)은 본문에도 비워 둡니다.

게이트가 문서(md)만 보면 코드 쪽 데이터가 빠져나갑니다. 그래서 같은 규칙을 코드에도 적용합니다.

- **일정표도 같은 법칙** — `src/data/schedule.ts` 의 `pending` 항목은 `dueText` 를 채울 수 없고,
  설명에 검증 안 된 수치를 쓸 수 없으며, 확인 창구 링크(공공 기관 도메인 또는 이 사이트)와
  `decidedBy`(그 값이 협약서·공지·원문 중 어디서 확정되는지) 를 반드시 가져야 합니다.
- **링크는 두 번** — 문서 본문·컴포넌트·체크리스트에 적힌 `/guide/...` 경로가 실제 라우트인지 검사하고(주석 속 예시는 제외),
  빌드 뒤에는 `dist` 의 모든 `href`·`src` 를 실제 파일로 되역해 확인합니다(`check:dist`).
- **제목도 검사** — `check:dist` 는 모든 화면 `<title>` 에 `(비공식)` 이 있는지와 canonical 1개를 확인합니다.
  공유 미리보기·브라우저 탭이 공식 기관 페이지처럼 보이는 것을 막는 지점입니다.
- `verification` 을 아예 적지 않으면 기본값이 `pending` 이라 수치 금지·검증 메모 요구가 함께 걸립니다(게이트 우회 방지).
- **`verified` 로 바꾸는 길도 막아 놓았습니다** — `pending` → `verified` 로 값만 고치면 수치 금지가 전부 풀리기 때문입니다.
  검증 완료 문서·항목이 수치·조항을 적으면 ① 그 자리에서 다시 확인할 수 있는 출처(`law.go.kr`·`nts.go.kr`·`hometax.go.kr`)와
  ② `제N조`를 인용하면 국가법령정보센터 원문 링크를 함께 요구합니다. 확인 창구가 이 사이트 링크뿐이면
  '자체 권장'임이 본문에 드러나 있는지 봅니다 — 기관 요구로 오해되면 안 됩니다.
  게이트는 출처의 **형태**를 검사하고 인용한 조문 값의 참거짓을 판정하지 못합니다. 그래서 값을 채울 때마다 원문을 직접 열어
  `decidedBy` 에 확인 날짜를 남기고, 확인하지 못한 것은 값 칸을 비웁니다(거짓을 줄이는 1차 장치는 '빈칸' 규칙입니다).
